## 一、为什么之前总在重复教学

问题主要出在骨架本身。对话切得多一点少一点，影响不大。

你的骨架是**按"估值流程"组织的**：从价值是什么，到读报表、预测、估值方法、不同公司，最后落到决策。同一个概念会在流程的不同阶段反复出现。这本身没错，因为真实的估值就是这样一步步往前走的。可是切成十几个对话、每个对话只看见自己那一段，每个对话都会以为"这个概念轮到我来讲"，于是从头再讲一遍。

## 二、核心设计：三层结构 + 一本台账

```
骨架层   framework/outline-v28.md      你的结构，不轻易改
台账层   framework/concepts.md         每个概念：唯一主讲位置 / 引用位置 / 统一符号 / 出处
内容层   content/5.x/…md               按节写正文
```

### 1. 概念台账（解决重复的关键）

每个概念登记一行：

| 概念 | 符号 | 主讲 | 引用于 | 出处 |
|---|---|---|---|---|
| 投入资本回报率 | ROIC | 5.2.1.1 | 5.2.2, 5.3.2.5, 5.4.2.9, 5.5.4.1 … | 麦3、6、7 |

### 2. 每个节点只扮演三种角色之一

- **主讲**：完整讲清概念、直觉、公式、出处差异（麦和达说法不一样时，在这里讲透）。
- **应用**：一句话链接到主讲位置（如"见 5.2.1.5"），然后只写**这个场景下的新问题**。
- **回顾**：在决策章（5.7）里串联前文，不再展开。

写作者每写一节，开头先列"本节新教 / 本节调用"，写完更新台账。

### 3. 全局把控：总编 + 写作 + 审校

在 Claude Code 里，台账和正文都是仓库文件，**状态是持久的**。这是和 ChatGPT 多对话做法的根本区别。

| 角色 | 做什么 | 实现 |
|---|---|---|
| 总编（全局） | 先通读骨架和两套书目录，产出概念台账、书→节点映射、写作顺序；每节写前派活、写后验收 | 主会话 |
| 写作 | 读台账，读对应书章原文，写一节 | 子 agent，一次一节 |
| 审校 | 对照台账查重复、查术语和符号是否统一、查[自]的观点有没有和书冲突 | 独立子 agent，不看写作过程，只看成稿 |

**写作顺序按概念依赖排，不按目录顺序。** 先写各概念的主讲节点（5.2.1、5.3.2、5.5.2 等"根"），再写应用节点。这样每个应用节点写的时候，前置概念都已经在仓库里了。

### 4. 为什么不靠"技能模板"，又不会写得生硬

生硬，通常是因为每节都套同一个"定义—公式—例子—小结"模板。我的做法是：

- **规则管流程，不管文风**：只约束"不重复主讲、要标出处、符号统一、和[自]立场一致"，不规定每节长什么样。
- **按节点类型换写法**：概念辨析、公式推导、操作步骤、案例、判断清单，写法各不相同。
- **用你的声音**：先从骨架里的 `[自]` 节点和 5.7.4 提取你的投资立场，写成一页"作者立场"，所有写作都以它为准。
- **样章先行**：先写 1 节样章给你改，你改过的样章就是风格标准，比任何规则都管用。

## 三、骨架本身的几处建议（可选，等你拍板）

1. **5.5.2.2 与 5.4.1 合并**：两者几乎逐条重复。建议 5.5.2.2 收缩成"增长率作为 DCF 输入的一致性要求"。
2. **5.4.2.2「稳定状态」并入 5.5.2.4.3**，5.4.2 只保留"预测期要足够长"。
3. **5.2.3.7 EVA 与 5.5.3.3.3 经济利润模型**：概念在 5.2.1.8 主讲，EVA/CFROI 作为"业界变体"放一处。
4. **5.1.3「为何价值最大化」与 5.7.1「市场是否由基本面决定」**：前者偏公司管理视角，你的框架是投资者视角，可以压缩。
5. **待补项 5.6.4.4/5.6.4.5**：三本书确实没有系统方法，建议保留为"判断清单"，不硬写公式。
6. **贯穿案例**：骨架里只有喜力（5.3.2.10）一个案例。建议选一家你熟悉的公司从 5.3 一路估到 5.7，每节的"应用"都落到它身上。
7. 你有意没收期权估值（达5、28–30，麦20），这点我会遵守，不把期权写进主线。
